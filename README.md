# KBO 투수 피로 신호 탐색

[![reproducibility](https://github.com/jinwon25/KBO-pitcher-fatigue/actions/workflows/ci.yml/badge.svg)](https://github.com/jinwon25/KBO-pitcher-fatigue/actions/workflows/ci.yml)

2020–2024년 KBO 투수 등판 기록으로 기존 피로도 지수를 재검증하고, 점수의 의미와 한계를 투명하게 보여 주는 재현 가능한 분석 프로젝트입니다. 제4회 중앙대학교 데이터 분석 학회 DArt-B 학술제 대상 수상작을 바탕으로 하되, 공개 저장소의 코드와 데이터만으로 확인할 수 없는 주장은 제거했습니다.

> 결론: 저장된 점수는 같은 경기의 WHIP·ERA·FIP·GS와 강한 기술적 연관을 보이지만, 회복실패와 부상 대리 라벨을 구분하는 능력은 무작위 수준에 가깝습니다. 따라서 교체 임계값이나 자동 기용 추천이 아니라 **과거 기록 탐색용 모니터링 신호**로만 사용합니다.

## 분석 결과

### 1. 0–100 점수는 확률이 아니라 전체 표본 내 순위다

최종 데이터의 `피로도지수_점수`는 `피로도지수`를 전체 17,528행에서 순위화한 백분위 값과 오차 `1e-14` 이내로 일치합니다. 80점은 “부상 확률 80%”가 아니라 **저장된 원점수가 전체 표본의 상위 20%**라는 뜻입니다.

![점수 정의](./reports/figures/01_score_definition.png)

### 2. 같은 경기 성과와는 연관되지만 예측력으로 해석할 수 없다

원점수의 행 단위 피어슨 상관은 WHIP `0.834`, ERA `0.637`, FIP `0.482`, GS `−0.389`입니다. 그러나 점수 개발 과정에서 경기력 관련 결과가 사용됐고 평가도 같은 표본에서 이뤄졌습니다. 아래 패턴은 유용한 기술 통계이지만, 미래 성과 예측이나 피로의 인과효과를 입증하지 않습니다.

![성과 지표와 점수 10분위](./reports/figures/02_outcomes_by_decile.png)

### 3. 72.6을 교체 임계값으로 사용할 근거는 재현되지 않았다

저장된 데이터로 재계산한 ROC AUC는 회복실패 라벨 `0.514`, 과거 노트북의 부상 대리 라벨 `0.508`입니다. 모두 무작위 기준 `0.5`에 가깝습니다. 과거 노트북은 설명에는 회복실패를 적었지만 실제 Decision Tree에는 `부상위험도`의 비결측 여부를 라벨로 사용했고, 산출 임계값도 원점수 `3.732`였습니다. 문서에 있던 `72.6`과 일치하지 않아 운영 임계값 주장을 철회했습니다.

![임계값 검증](./reports/figures/03_threshold_validation.png)

## 무엇을 고쳤나

- 2025년 단일 시즌·선발 투수 분석이라는 설명을 실제 정본 데이터 범위인 2020–2024년·선발/불펜으로 수정했습니다.
- WHIP를 입력에 포함해 WHIP를 다시 예측하던 목표 누수 모델과 GS 설명 불일치를 제거했습니다.
- 서로 다른 날짜의 두 투수를 한 모델로 비교해 자동 기용을 권고하던 앱을 과거 기록 탐색 도구로 바꿨습니다.
- 원점수와 0–100 점수의 관계, 중복 키, 기간, 결측률, 핵심 지표를 자동 검증합니다.
- 대표 분석을 하나의 [노트북](./notebooks/analysis.ipynb)과 재사용 가능한 [분석 모듈](./kbo_fatigue/analysis.py)로 정리했습니다.
- 테스트·리포트·노트북 실행을 CI에서 다시 확인합니다.

검증 근거와 폐기한 주장에 대한 상세 기록은 [방법론과 검증 노트](./docs/METHODOLOGY.md)에 있습니다.

## 앱

앱에서는 두 투수의 점수 백분위 추이와 특정 등판의 투구수·휴식일수·성과를 나란히 탐색할 수 있습니다. 자동 추천, 부상 확률, 안전 임계값은 제공하지 않습니다.

```bash
python -m streamlit run app/역전점_앱.py
```

파일명 `역전점_앱.py`는 기존 링크 호환을 위해 유지했으며, 현재 앱은 역전점 모델을 실행하지 않습니다.

## 재현 방법

Python 3.11 기준입니다.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
make check
```

`make check`는 다음을 순서대로 실행합니다.

1. 데이터 계약과 핵심 수치 테스트
2. 표·그림·`metrics.json` 재생성
3. 링크와 대표 노트북 무결성 검사
4. 대표 노트북을 처음부터 끝까지 별도 출력으로 실행

앱만 실행할 때는 `requirements.txt`로 충분합니다. 과거 연구 노트북이나 크롤러를 재현하려는 경우에만 `requirements-legacy.txt`를 추가로 설치해야 합니다.

## 한계와 다음 실험

- 피로도 원점수를 처음부터 재생성하는 완결된 파이프라인이 저장소에 남아 있지 않아 **현재는 저장된 점수의 감사와 탐색**만 완전히 재현됩니다.
- `부상위험도`는 58.7%가 결측이고 실제 부상 발생 라벨로 검증되지 않았습니다.
- 같은 경기 결과가 점수 개발과 평가에 함께 사용돼 순환 논리와 목표 누수 가능성이 큽니다.
- 다음 단계는 사전에 정의한 workload-only 피처, 시간 순서 분할, 선수 단위 그룹 검증, 외부 부상·회복 라벨을 갖춘 별도 연구 설계입니다.
