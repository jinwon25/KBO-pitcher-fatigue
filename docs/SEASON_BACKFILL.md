# 경기 식별 및 시즌 백필 계약

## 고정 자료와 신규 경로

2020–2024 정본 및 기존 raw/processed/external 데이터는 수정하지 않습니다.
기존 분석·앱·`make check`의 입력도 그대로입니다. 2026은 완결본으로 편입하지 않습니다.

신규 MYKBO 수집은 `crawlers/투수_크롤링.py` →
`kbo_fatigue/appearances.py` → `scripts/stage_season.py`를 거칩니다.
출력은 `data/staging/<year>/` 안의 새로운 CSV와 해시 manifest로 제한됩니다.
같은 경로 덮어쓰기는 거부합니다. 검증 전에 오류가 나면 CSV를 쓰지 않습니다.

| 필드 | 계약 |
| --- | --- |
| PlayerID | `mykbo:player:2302`처럼 원천 선수 ID 보존 |
| GameID | `mykbo:game:13023`처럼 원천 경기 ID 보존 |
| GameURL | 추적 가능한 원천 경기 링크 |
| Date | 원천 경기의 날짜. 표시 시각으로 추정하지 않음 |
| Year | 포함된 경우 Date의 연도와 일치 |

`(PlayerID, GameID)`는 비결측·유일해야 합니다. 같은 경기 ID에 여러 날짜를
허용하지 않습니다. 병합은 양쪽 키 집합이 같아야 하며 metadata 충돌과 지표
덮어쓰기를 거부합니다. 한쪽만 존재하는 행은 오류 메시지의 집계로 확인한 뒤
수집 범위를 보완해야 합니다. 날짜 fallback, cumcount, 행 순서 매칭,
`drop_duplicates(keep='first')`는 사용하지 않습니다.

다른 사이트의 ID를 직접 비교하지 않습니다. 출처가 다른 자료는 양쪽 원천 URL과
경기별 대조 근거가 있는 경기/선수 crosswalk를 검토한 뒤 공통 네임스페이스로
변환해야 합니다. 한 경기만 등판한 투수에게 '그날 첫 번째 등판'을 1차전으로
배정하는 방식도 금지합니다. 경기 순서가 필요한 피로도 계산은 검증된 KST 시작
시각이나 공식 DH 순서를 별도로 확보해야 하며, GameID 문자열 정렬은 시간순이 아닙니다.

## 2025 회귀 사례

기존 스냅샷의 13개 중복 키에는 26행이 속합니다. 5월 10일 4행,
5월 17일 22행입니다. 각 쌍에 같은 `Time`이 저장돼 있어 시간으로 복원할 수 없습니다.
이 원본을 수정하거나 26행에 임의 ID를 붙이지 않습니다.

원천 box score로 확인한 최소 사례를
[`mykbo_doubleheaders_2025.csv`](../tests/fixtures/mykbo_doubleheaders_2025.csv)에 둡니다.

- 5월 10일 장현식: 경기 13007(14구), 13011(16구).
- 5월 17일 박영현: 경기 13023(12구), 13028(17구).

이는 실제 원천 ID 검증용 fixture입니다. 전체 13그룹의 복원 완료를 뜻하지 않습니다.
테스트는 기존 13그룹 검출, 링크 정규화, 양쪽 행 순서 반전, 중복/결측/미매칭 차단,
선수 동명이인, 2025/2026 staging 격리, 정본 SHA-256을 검사합니다.

## PBP 경로의 경계

기존 `build_pbp_features.py`는 날짜 단위 재현 경로입니다. 저장된 2023–2024
파생 자료에는 `pbp_source_games=2`인 36행이 있습니다. 이번 작업에서 역사적
분석 수치나 파생 파일을 바꾸지 않으며, 이 한계는 그대로 남습니다.
신규 연도를 날짜 경로에 넣으면 오류가 발생합니다.

백필 개발에서 `build_features(paths, None, game_level=True)`를 사용하면
`(game_pk, pitcher)`로 구속·투구수·진입 상황·RE24를 각각 집계하고
`pbp:game:*`, `pbp:player:*`를 보존합니다. 기존 정본과 날짜로 결합하지 않습니다.
공개 PBP 다운로드 CLI는 기존 고정 2023–2024 revision만 받습니다.
2025/2026 PBP 원본 확보, 라이선스·해시 고정, MYKBO와의 crosswalk는 별도 작업입니다.

## 전체 시즌 검증 전 필요한 조건

1. 원천 경기/선수 ID가 있는 2025 전체 시즌 로그를 재수집합니다.
2. 공식 최종 일정의 실제 완료 경기와 수집 경기 목록을 대조합니다. 취소·재편성·
   서스펜디드 경기와 DH 양 경기를 확인하고 대상 선수의 시즌 등판 수도 대조합니다.
3. 날짜만 남은 2025 기존 부가자료는 경기별로 재수집하거나 근거 있는 crosswalk를
   확보합니다. 전체 시즌 부상 라벨과 관측 기간도 별도 확인합니다.
4. staging에서 일대일 병합·행 수·지표 합계·누락을 검증합니다. 2026도 종료 후 같은
   절차를 적용합니다. 현재는 부분 수집 자료만 staging에 저장할 수 있습니다.
5. 별도 검토 후 외부 holdout에 편입합니다. 현재 앱의 날짜 단위 계약·미래 등판
   정렬도 경기 단위로 이행해야 하므로 staging 파일을 정본에 단순 append하지 않습니다.

manifest의 `identity_validated=true`는 키 검증 통과만 의미합니다.
`season_complete=false`, `holdout_ready=false`는 자동으로 true가 되지 않습니다.
현재 전체 시즌 백필을 위한 안전한 저장·결합 경로는 준비됐지만, 전체 원천 수집과
crosswalk·일정/라벨 대조가 완료된 것은 아닙니다.

```bash
make check
```

브라우저 수집은 이 명령의 범위가 아닙니다. 오프라인 회귀 및 정본 분석·보고서·
무결성·노트북 재현을 검증합니다.
